# 04 日常用法

## 模式选择
- **默认 Chat，思考强度开高**（Neon-high）。Chat 能调思考强度，Task 不能（社区猜 Task 固定 medium）。
- **Task** 只用于“交代清楚、让它自己一口气跑完”的长任务。缓存只活 2–5 分钟，中途停顿超过 2 分钟每步消耗涨 3.7 倍以上，所以别开了 Task 又半路去干别的。
- 有人报过 Task 模式调自定义 MCP 报 `Transport for env PROD not found` 而 Chat 正常；我们没遇到，但 Chat 更稳。

## 写提示词的规矩
1. 开头 `@runabout`。
2. 用英文写指令，结尾 `Reply in Chinese.`
3. 写清**工作目录**：`Work only in /workspace/项目路径.`
4. 先读交接文档：项目有 AGENTS.md / docs 就读它；没有就让它建 `NOTES.md`。
5. 写清**能做什么、不能做什么**：只读任务写 `READ-ONLY: do not delete, move, reset, clean or modify anything.`
6. 写清**要交付什么格式**：比如“一张表，列：路径、大小、是什么、能否删除、怎么恢复”。
7. 慢操作（大目录 du、构建、dev server）让它**后台运行再读输出**：`run it in the background and read the output when done.`
8. 改代码前要计划：`Tell me your plan before editing.` 改完要 diff：`Show git diff before committing.`
9. 在新分支干活：`Create a branch before editing.`

## 控制上下文（防降智）
- 一个功能一个对话。
- 交接文件：每次开头读、结尾更新：`Update NOTES.md with what changed and next steps.`
- 让它用搜索找代码，不要一口气读整个仓库。
- 单个文件保持小（有人定 ≤300 行），它改得更准。

## 和 IDE agent 分工
- Gemini 网页（额度多）：调研、读代码、分析、架构规划、写计划。
- agy / Codex / Claude Code：精细多文件修改、一次执行到位。
- 让 Gemini 把计划写进项目文件，IDE agent 直接读。

## 额度
- 只能看百分比：`gemini.google.com/usage`（5 小时窗口 % 和每周 %，不按模型拆分）。手机 App：菜单 → 齿轮 → Usage limits。
- 网上“每周 10–20 亿 token”是拿每步掉的百分点乘估算 token 反推的量级，不是官方数字。
- 高思考更耗。头几天看一眼 usage 页，摸清一天能干多少。

## 安全习惯
- 全开 Always allow 时，别让它一边浏览不可信网页/读陌生文件一边跑 shell（提示注入）。
- 删除类操作永远两步：先只读出报告，你确认后再单独发删除指令。
