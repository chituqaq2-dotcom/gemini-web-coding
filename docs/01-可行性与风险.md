# 01 可行性与风险

## 能做什么
- Gemini 网页版（选 Neon 等模型）通过 MCP 调你机器上的工具：读文件、搜代码、打补丁、跑 shell（构建、测试、git）。
- Chat 和 Task 两种模式都能调（我们实测都能用）。手机 App 连好后也能用。
- 用的是订阅额度（每 5 小时一个窗口 + 每周上限），不花 API 钱。

## 门槛（Google 官方要求）
- 18 岁以上、**人在美国**（代理节点要稳定在美国）。
- **个人** Google 账号，工作 / 学校账号不行。
- 必须打开 Gemini **History**（代码会留在 Google 那边，可能被用于审核和改进，公司代码慎用）。
- 自定义应用官方只支持**英文**。中文多半也能调，但不保证，用英文下指令最稳。

## 做不到的
- 不能反过来让别的程序（Claude Code、agy、你自己的 App）调用 Gemini 网页的额度。那要靠逆向，违反 ToS。
- 不是 IDE 体验，是“在网页里聊天写代码”。精细多文件修改，IDE 里的 agent 还是更顺手。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 公网暴露 shell | runabout 开 OAuth 登录；Cloudflare Tunnel 不开入站端口；强密码 |
| 提示注入（网页/文件里藏指令诱导执行命令） | 容器只挂项目目录；不在机器上放密钥/token；别让它边读不可信内容边跑 shell |
| 改坏 / 删掉文件 | 所有项目 git 管理并常推远端；危险任务先 READ-ONLY |
| 权限过大 | Docker 非 root 运行、`no-new-privileges`、`SUDO_NOPASSWD=false`、限制内存 |
| 地区功能消失 | 属于可用性问题，一般不至于封号 |

> runabout 作者自己也说它**不是沙箱**：以什么用户运行，agent 就有什么权限。隔离靠 Docker 挂载范围。
