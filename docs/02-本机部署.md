# 02 本机部署（Windows 11 + WSL2 + Docker）

## 为什么放本机而不是 VPS
- 代码就在本地，IDE、agy、Codex 和 Gemini 改的是**同一份文件**，编译也快。
- MCP 来回只传命令和 diff，几 KB 文本，带宽不是问题；但小水管 VPS 编译慢。
- 代价：关机就用不了。

## 资源占用
i5-13400 / 32GB 这种配置绰绰有余。runabout 待机几十 MB，只有编译/测试时吃 CPU。用 `.wslconfig` 限制 WSL：

```ini
[wsl2]
memory=8GB
processors=4
vmIdleTimeout=-1
networkingMode=mirrored
```

`networkingMode=mirrored`：Windows 上开了本地代理时必须加，否则 WSL 用不上代理（启动时会提示“检测到 localhost 代理配置，但未镜像到 WSL”）。

后台运行，没有窗口，不碰鼠标键盘，不影响日常办公。**不要装 Docker Desktop**，直接在 WSL 里装 Docker Engine。

## 目录规划（示例）
| 东西 | 位置 |
|---|---|
| WSL 系统盘 | `E:\WSL\runabout`（C 盘紧张就放别的盘） |
| runabout 源码 | WSL 内 `~/runabout`（不要放 /mnt 下） |
| 你的项目 | `D:\Projects` → 容器里 `/workspace`，**只挂这一个** |

## 让本地 agent 执行
整个部署交给本地任意能开终端的 agent（Codex CLI、agy 等）执行，提示词见 [prompts/deploy-local-agent.md](../prompts/deploy-local-agent.md)。

关键原则（写进提示词）：
- 小问题（缺组件、参数不支持、换镜像）**让它自己修，事后汇报**；只在 重启电脑 / 输密码 / 填隧道 token / 删除覆盖已有数据 / 挂载额外路径 时停下。早期写“报错就停”，结果它在第一步就停了，很烦。
- 密码和 token **只由你本人在终端里输入**，不给 agent、不写进文件和日志。
- root 命令用 `wsl -d Ubuntu-24.04 -u root -- <命令>`，不用 sudo，不把 Linux 密码给 agent。

## 步骤概览
1. 启用 WSL 和虚拟机平台（全新电脑需要，见踩坑 #1），重启。
2. 安装 Ubuntu-24.04 到 E 盘，写 `.wslconfig`，`wsl --shutdown`。
3. 创建 Linux 用户（你自己在终端里建，第一次进 WSL 时会提示）。
4. `/etc/wsl.conf` 开 `[boot] systemd=true`；装 Docker Engine，用户加 docker 组，开机自启。
5. `git clone https://github.com/noir017/runabout ~/runabout`。
6. 配置 `deploy/.env`、`docker-compose.override.yml`、`config.yaml`（见下）。
7. 你自己运行 `hash-password` 设 runabout 登录密码。
8. Cloudflare 建隧道，你自己把 token 粘进 `.env`。
9. `docker compose up -d --build`，验证。
10. 开机保活任务。

## 配置要点

### `deploy/.env`
```
RB_BASE_URL=https://mcp.你的域名        # 末尾不要斜杠
AGENT_UID=1000                           # id -u
AGENT_GID=1000                           # id -g
SUDO_NOPASSWD=false
MEM_LIMIT=4g
CF_TUNNEL_TOKEN=                         # 你自己填
```

### `deploy/docker-compose.override.yml`（不要改原 compose）
- mcp 服务的 `/workspace` 挂载改成 `/mnt/d/Projects:/workspace`；除了它、`config.yaml`、`mcp-data` 不挂任何路径。
- 加上 cloudflared 服务（原 compose 里是注释掉的），用 `.env` 的 `CF_TUNNEL_TOKEN`。
- mcp 加 `security_opt: [no-new-privileges:true]`。
- 先 `docker network create cloudflared`。

### `deploy/config.yaml`（从 `configs/config.example.yaml` 复制）
```yaml
server:
  listen: "0.0.0.0:8484"
  base_url: "https://mcp.你的域名"       # 必须和 RB_BASE_URL 完全一致
  allowed_origins: ["https://gemini.google.com"]   # 加进去
auth:
  users:
    - username: "你的用户名"
      password_hash: "$2a$..."           # hash-password 生成
  allow_unauthenticated_initialize: true # Gemini 必须开！
tools:
  shell:
    default_workdir: "/workspace"
# audit 保持开启
```

密码：8 位起，最长 72 字节。`docker compose run --rm --no-deps mcp hash-password`，你自己输两遍，只把 bcrypt 哈希写进 config。

### Cloudflare Tunnel
- Zero Trust → Networks → Tunnels → 新建（remotely managed）。
- Public hostname：`mcp.你的域名` → Service `http://runabout:8484`（**容器名，不能写 127.0.0.1**，否则 502）。
- token 在 Configure 页安装命令 `--token` 后面，`eyJ` 开头。你自己用 nano 粘进 `.env`，别发给任何人（包括 AI）。

### 开机保活
Windows 任务计划：登录时触发、隐藏运行 `wsl.exe -d Ubuntu-24.04 -- sleep infinity`。

## 验证清单
- `docker compose ps`：runabout healthy、cloudflared running。
- `curl -s https://mcp.你的域名/healthz` → 200。
- `~/runabout/skills/runabout-deploy/smoke.sh https://mcp.你的域名`：开了 `allow_unauthenticated_initialize` 后会有 **2 项预期失败**（脚本以为匿名 initialize 应返回 401），正常。
- 未登录调 `tools/list` 应返回 401。
- 容器里 `ls /workspace` 看得到项目、`ls /mnt` 为空，能新建删除测试文件。
