# 用户习惯与偏好（给接手 agent）

来源：2026-11-23～24 与 Hark 的对话，用户原话或明确表态；标“推断”的是我从行为归纳的。

## 沟通
- 中文；简短，先结论；不要寒暄、不要复述、不要一堆选项，给一个推荐。
- 常问“下一步是什么”：直接给下一步和可复制的指令。
- 问“我们到底在做什么”时：三五句大白话按事情讲（做了哪几件、各自到哪了），不讲过程（2026-11-24 用户嫌折腾半天看不懂）。
- 讨厌来回停顿和重复确认；小问题自己修、事后汇报。
- 一个目标给一段完整指令，不要一小步一小步试（2026-11-23 20:17）。
- 给 Gemini 的指令每次写明模型、模式、思考强度、新对话与否（2026-11-23 21:07；11-24 再次强调）。
- 用户会把 Codex 的整段回报直接贴过来：我读完给结论、要他做什么，并把有用的写进仓库。推断：他通常不细看长回报，靠我提炼。
- 指令卡片的语言：发 Gemini 的是英文，发 Codex 的是中文；卡片标题写清“发给谁”，用户曾把 Codex 指令误当成 Gemini 的（2026-11-24）。

## 分工
- Gemini（runabout）：写代码、读仓库、出方案。额度随便用（2026-11-23 20:17）。
- Codex（本地 agent）：Windows 侧测试/打包/提交/部署/浏览器验证、git 机械活、清理执行。用户不想再手动粘 PowerShell（2026-11-23 21:41：“体验太差”）。
- 用户本人：App 里手动验收、输密码/登录、清空回收目录、决定删什么。

## runabout 权限
- 用户嫌限制反人类（11-25：“你搞那么死”“不删文件、不 git push？你又来了”）：除了容器只挂 D:\Projects 这一道，命令、目录、删除、推送都放开（11-25 已落实），不要再加新限制。删除用户数据前出清单的习惯仍保留（下一节）。

## 安全与删除
- 密码、token 只由用户本人输入。
- 删除：带编号清单 → 用户勾选/说“可以” → 挪回收目录（不直接删）→ 用户自己清空。
- 本仓库公开：不写域名、密钥、隧道 ID、坐标。
- 油猴脚本改动先问用户。

## 记录
- 有用的信息当轮写进本仓库，不许只留在对话里（2026-11-23 21:29）。
- 本仓库提交推送不用问。
- 更新仓库时要勘误、删改、合并同类、去冗余，不是流水账；但信息不能压缩失真（2026-11-25）。

## 诊断类提示词（2026-11-25）

- 开放式诊断（看一个大项目怎么继续）不要预设标准答案：别拿别人的产品或宣传页当目标，别默认某类功能是冗余。项目定位也只当用户目前的想法给出，不写成定论，允许 Gemini 质疑，让它自己判断（用户补充：“讲清核心价值也不一定对，话不要说太死”）。用户原话：“给的太具体了，反而会限制我的项目本身和 gemini 自己的判断。”
- 大项目的判断型分析用 high，不套“分析用 medium”的默认（用户 11-25 提出）。

## 设备与环境（推断，供写命令时参考）
- 主要在 Windows 桌面网页端用 Hark，偶尔用 Android 手机。
- 默认终端 PowerShell；Node 有 nvm-windows（20.17）和 D:\Program Files\DevTools\nodejs（26.x）两套，测试用后者。

## 任务结束后读额度（2026-11-25）

额度由 Hark 自己读（只读接口），不让用户截图、不让用户登录 Google。任务一完成先读一次额度；跟任务前一样就三分钟后再读，还一样就再等三分钟，直到读数变了再记账（最多等 30 分钟，仍不变就记“未变，可能滞后”）。不要固定等一个时长。
