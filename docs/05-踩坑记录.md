# 05 踩坑记录

按遇到的顺序记。

### 1. `wsl --update` 不存在 / 只打印帮助
**现象**：新电脑运行 `wsl --update` 退出码 1，帮助里只有 --install / --list / --status。
**原因**：没装真正的 WSL，只有系统自带的 wsl.exe 空壳。
**解决**（管理员 PowerShell）：
```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
wsl.exe --install --no-distribution   # 不支持就 winget install --id Microsoft.WSL -e
```
DISM 返回 3010 = 需要重启。重启后 `wsl --version` 确认。

### 2. 本地 agent 动不动就停
**原因**：提示词写了“报错就停，不要自己换方案”。
**解决**：改成“小问题自己最小化修复并事后汇报，只在 重启 / 密码 / token / 删除覆盖数据 / 额外挂载 时停”。

### 3. 重启后 agent 会话断了
Codex CLI：同目录管理员 PowerShell 运行 `codex resume --last`，再发“继续”。接不回来就重贴部署提示词并说明进度。

### 4. Ubuntu 下载中断
官方源中断时改用国内镜像（如中科大），**安装前核对 SHA-256**。

### 5. 首次进 WSL 默认用户名是 administrator
第一次 `wsl -d Ubuntu-24.04` 会让你建用户，提示的默认名就是 Windows 用户名，删掉改成你想要的。这个 Linux 密码和 runabout 登录密码是两回事，建议不同。

### 6. “检测到 localhost 代理配置，但未镜像到 WSL”
`.wslconfig` 加 `networkingMode=mirrored`，`wsl --shutdown`。之后 GitHub、Docker 镜像都能走 Windows 代理。

### 7. agent 要 sudo 密码
别给。让它用 `wsl -d Ubuntu-24.04 -u root -- <命令>` 从 PowerShell 跑 root 命令。

### 8. 项目在 D 盘，Windows 弹窗提示跨文件系统 git 慢
点“不再显示”。放 D 盘是为了让 Windows 上的工具也能用同一份文件，普通项目感觉不到慢。特别大的仓库卡了再单独搬进 WSL。

### 9. Docker 构建下载超时 / 502
构建时走本机代理，Debian 源换国内镜像。本地复制一份 `Dockerfile.local` 改源；**以后 git pull 更新时先 `diff -u Dockerfile Dockerfile.local`**，上游改了构建步骤要同步。

### 10. 域名返回 530
隧道没连上：token 没填 / 没生效，或 cloudflared 容器没起来。

### 11. 隧道 502
Public hostname 的 Service 写成了 `http://127.0.0.1:8484`。要写容器名 `http://runabout:8484`，且两个容器在同一个 docker 网络。

### 12. Gemini 说“不是有效的 MCP 服务器”
没开 `auth.allow_unauthenticated_initialize: true`。Gemini 第一次握手不带认证。开了不会放开工具权限（未登录的 tools 调用仍是 401）。

### 13. smoke.sh 15/17
那 2 项失败是脚本预期匿名 initialize 返回 401，和第 12 条的开关冲突，正常。

### 14. 设置里找不到 Connected Apps
在 **Personal Intelligence** 里面；或直接打开 `gemini.google.com/customize/connectors`。

### 15. 添加时要填 Client ID / secret 吗
不用，留空。runabout 支持动态客户端注册。

### 16. 忘了把应用改成英文名
没有重命名按钮，Disconnect 后重加。旧授权留在服务端不碍事。

### 17. 不加 @ 它不调工具
提示词里带 `@runabout` 强制调用。

### 18. 交接文件放哪
不是 `/workspace` 总根目录，而是**每个项目自己的文件夹**，和它的 README 放一起。项目已有 AGENTS.md / docs 体系就直接用，不必再建 NOTES.md。

### 19. 大项目统计磁盘很慢
挂载的是 Windows 盘（经 WSL 跨文件系统），8 万个文件 `du` 很慢。让 Gemini 后台跑、跑完再读。

### 20. 设置里全选了 Always allow，对话里还是一个个弹 Allow
连接时的权限设置不一定生效到每个工具；第一次调用某个工具时还会弹窗（如 shell kill、执行 shell 命令）。在弹窗里点 Always allow，之后不再问。每次弹窗都等于多一轮对话，费额度。

### 21. 装完 WSL 弹出“欢迎使用 WSL”企鹅窗口，要不要一直开着
不用，直接关。那只是 WSL 设置/欢迎页，跟服务运行无关；容器和隧道靠后台的保活计划任务跑。关窗后可用 `wsl -l -v` 确认发行版仍是 Running。

### 22. 容器里 `git status` 一堆 M，但其实没改
仓库在 Windows 盘上、从 WSL 容器里看时，文件权限位和换行符跟 Windows 侧不一致，git 会把大量文件标成修改（M）。判断有没有真改：`git diff --stat -w --ignore-cr-at-eol | tail -3`，或只看 `git diff --diff-filter=D --name-only`（有没有被删的追踪文件）。想彻底消除：在该仓库里 `git config core.fileMode false`（在 Windows 侧执行，别在容器里改用户的全局配置）。让 Gemini 校验时把这条写进提示词，免得它误报。

### 23. 清理后想验证，Windows 里 `pnpm` 不认识
Windows 侧可能没全局装 pnpm（项目依赖是别的工具装的）。`corepack pnpm build` 能起步，但项目脚本里如果再调 `pnpm run ...`（嵌套调用）还是会报“pnpm 不是内部或外部命令”。一劳永逸：管理员 PowerShell 跑 `corepack enable pnpm`，或普通 PowerShell 跑 `npm install -g pnpm`，重开终端。另外，只搬走了 output 快照和 `.git` 临时包时，构建根本不受影响，真正该验的是仓库完整：`git fsck --no-dangling`，没有 error 再清空回收目录。

### 24. 「执行 shell 命令」设成 Always allow 后过一会儿又变回 Always ask
现象：设置页里其他工具都保持 Always allow，唯独 shell 反复被重置，对话里又开始弹 Allow；“Last synced” 时间每次都是刚刚。
原因（推测，2026-11-23）：runabout 给 shell 工具标了 `destructiveHint: true` + `openWorldHint: true`。Gemini 每次重新同步工具时，对“破坏性且能联网”的工具强制回到 Always ask。apply_patch 只标了破坏性，就没被重置。
解法（实验中）：把 `internal/tools/shell.go` 里 shell 的 `OpenWorldHint` 改成 false 再只重建 runabout 服务。这是有意报假（shell 其实能联网），只影响客户端弹不弹窗，不改功能；本地 agent（如 Codex）可能会拒绝改，属正常，用户自己跑 sed + `docker compose up -d --build <服务名>` 即可。撤销：`git checkout` 该文件再重建；升级 runabout 时 `git stash && git pull --ff-only && git stash pop`。还会跳回就再试 `DestructiveHint` 也改 false。

### 补充（2026-11-23 20:04）
- 打了 OpenWorldHint 补丁后，设置页还是在一次“Connecting...”重连后被打回：这次 shell 和 Shell kill 一起变回 Always ask（Apply patch、Shell output 等没变）。查过：补丁还在（shell.go:91 OpenWorldHint=false）。Shell kill 只标了 DestructiveHint，和 Apply patch 一模一样，但只有前者被重置——说明不是标记决定的，更像 Gemini 对“执行命令类”工具有自己的规则，改标记治不了。对策：接受；提示词里让 Gemini 把逐项操作写成一个脚本一次跑完，少调 shell 就少弹窗、少花额度。

### Windows 仓库在 WSL 侧：没外网、依赖不能跑、换行符不同（2026-11-23）
Gravity 在 WSL 里看：runabout shell 外网 HTTP 被拦（PERMISSION_DENIED）；node_modules 是 Windows 装的，vitest/esbuild 跑不了；仓库历史 LF、Windows 工作区 CRLF，Linux git 没设 autocrlf。对策：Gemini 只改文件、保留 CRLF、不碰 git；测试/打包/提交写成一段 PowerShell 在 Windows 跑。大任务单轮会撞工具次数上限：第一轮读完出方案，第二轮同对话直接落地、合并补丁。

## 给用户粘贴的 PowerShell 里别写 exit（2026-11-23 Gravity）
**现象**：`if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }` 一触发，整个终端窗口直接关掉。
**原因**：粘进交互式 PowerShell 的 exit 退出的是终端本身。
**做法**：整段包进 `& { ... }`，失败时 `Write-Host ...; return`，只停脚本不关窗口。

## Gravity 的 jsdom 测试报 ERR_REQUIRE_ESM（2026-11-23）
**现象**：vitest 显示其余全绿，但有 2 个 Unhandled Error：html-encoding-sniffer@6 require() 了 ESM 的 @exodus/bytes；用到 jsdom 的测试文件（如 weatherSourceSettings / characterAwarenessSettings）根本没跑，退出码 1。
**原因**：本机 Node 太旧（20.17），是环境问题，不是改动的锅。
**做法**：实测开关没用——本机 Node 20.17，而依赖 undici@8 要求 Node ≥22.19，开了开关又报 undici `reading 'bind'`。唯一解是用新 Node。用户机器上 nvm-windows（C:\nvm4w\nodejs，当前 20.17）排在 PATH 最前，盖住了 winget 装的 LTS 26.13.1（D:\Program Files\DevTools\nodejs）；临时办法是当前窗口 `$env:Path = 'D:\Program Files\DevTools\nodejs;' + $env:Path` 再跑，不动 nvm。看结果时核对“列了几个文件、跑了几个”，别只看 passed。


## Gravity：public/amsg-worker.bundle.js 是忽略文件（2026-11-23）
**现象**：git add 列表里带上它，整条 add 失败（"paths are ignored"）。
**做法**：build:workers 生成的两份 amsg bundle 只提交 `worker/amsg/worker.bundle.js`；git add 列表只写 `git status --short` 里真出现的路径。

## Gravity 部署脚本在 Windows 调 npx 报 ENOENT（2026-11-23）
**现象**：仓库的 Worker 部署脚本在 Windows 上 spawn npx 失败。
**做法**：Codex 在临时副本里给那处 spawn 加 shell 执行后部署成功，仓库脚本未改。以后要修就在脚本里对 win32 用 `shell: true` 或调 `npx.cmd`。
